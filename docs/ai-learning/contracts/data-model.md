# Data model 0.1.1

frozen-ddl.sql is a precise field/type/index blueprint split into V001 (T01), V002 (T02), V003 (T03), V004 (T05). It is not an applied migration. Each owner provides its actual migration and T07 verifies an isolated MySQL database, both clean initialization and upgrade. Never run the legacy oj.sql/course.sql on existing data: their actual code contains DROP DATABASE / DROP TABLE, regardless of comments claiming incrementality.

All new ID columns use signed BIGINT auto-increment. Foreign IDs are BIGINT; wire conversion is decimal string. New timestamps are UTC DATETIME(3), written explicitly rather than inherited Date/host-local defaults. Existing tables and timestamps are not rewritten. Each migration is applied once with an execution ledger and checksum; a second application is rejected/skipped before DDL, not made safe by silently swallowing arbitrary ALTER errors. DDL may auto-commit, so back up and test restore first.

Preflight checks: database name, existing user/problem/submission/course/course_resource/course_problem tables, old submission columns and the migration ledger. Never migrate a partially applied unknown schema as if it were clean. Schema inspection detects conflicting existing columns/indexes and reports them. Actual migration runner/commands and database compatibility belong to T07. No database migrations are executed automatically on application startup in T00.

V001 enrollment statuses are ACTIVE/INACTIVE; unique(user_id,course_id) is permanent. Rejoin updates the same row and joined_at; duplicate active join preserves joined_at. Lesson status DRAFT/PUBLISHED/DISABLED is separate from active logical deletion. All association tables use active=0/1 with unique pair/triple keys, and rebind updates the existing row. Sorting is sort_order ASC, id ASC. No cascade physically deletes a student's history.

V002 event source CLIENT/JUDGE/ASSISTANT. Processing PENDING/PROCESSING/PROCESSED/FAILED; lease_owner and lease_expires_at govern conditional claims, completion and recovery. event_id is globally unique. Client UUID keys that belong to another user remain private and are rejected; same-user same-ID changed payload is 409. payload_hash is SHA-256 of normalized event semantics, including identity/scope/type/source/payload and client time; generated server time is excluded to allow backend retries. Server event IDs use submission:{id}:judged:{revision}; first terminal save sets judged_revision=1 under the result-save transaction, duplicate/late callbacks are ignored. Rejudging is not implemented. All terminal save paths must insert the event in that local transaction after sandbox execution; existing judge entry-point integration is still pending T07.

Independent submissions keep null course_id/lesson_id. lesson_id requires course_id; course source is validated at submission and immutable afterward. assistance_level is NONE/HINT/SOLUTION/UNKNOWN; existing submissions default UNKNOWN. No inference that a user received no external help is made. UTC conversion of legacy submission dates requires a defined JDBC timezone in T07.

lesson_progress is one row per user/lesson; resource_progress stores versions independently as an array of {resourceId,resourceVersion,intervals,lastPosition,lastOccurredAt}; recordedSeconds is computed from merged intervals on read, not another stored counter. ResourceRef.version is initially the stored resource ID as canonical string because existing upload creates immutable rows and has no replace-file API. If replacement is later introduced it must create a new version identifier and trigger knowledge invalidation; metadata updates must not change content version. Merge intervals, never sum raw event durations. Event's durationSeconds is client evidence for bounds, not trusted asset metadata. Current record calls this recorded progress. Self-reported completion is explicitly separate.

V003 one stable knowledge_document per existing resource (unique nullable resource_id); teacher notes have resource_id=null, source_type=NOTE and note_text. resource sources use source_type=RESOURCE. document.version is desired version, active_version is the last complete indexed version. Failed replacement can keep old active_version until new completion, but source deletion/course invalidation immediately removes access. Immutable chunks are unique per document/version/ordinal. citation_id is chunk:{id}:v{version}. Resource version, knowledge document version and citation version are distinct fields.

Each ingestion job is unique(document_id,version), snapshots teacher text and hash, and has QUEUED/PROCESSING/READY/FAILED/UNSUPPORTED states, attempts and conditional lease fields. Retries only touch the same version; maximum 3 attempts, configurable. Chunk publication and active_version switch occur together; compare desired version under lock so late work cannot supersede a newer job. Source files are located by saved resource IDs, never model-provided paths. Text is bounded to 2000 characters per indexed chunk, candidate limit 200, result limit 5, total returned text 10000 characters, all configurable bounded defaults.

V004 conversation.user_id is sole ownership evidence. active_message_id is a transactional compare/set lock, not a per-process global student. User and assistant rows share a UUID request key with unique(conversation_id,client_message_id,role). Request hash covers body/mode/context. AI message status matches StreamEvents; user rows are persisted as COMPLETED, assistant rows transition by leased generation. Empty citations=[]; usage_json nullable. Tool audit stores names/status/duration and truncated sanitized summaries only. Never persist signed credential, Session or model key.

Lecture/source cleanup, association deletion and course/resource/problem deletion are logical first. Historical chunks/events/messages may remain, but current permissions and active-version checks control every query and file open. A retained row is not authorization to read an unavailable course or source.
